# 带下界和锁定边的最小费用流 / Minimum-Cost Flow with Lower Bounds and Fixed Edges

本页定义子协议。组合后的入口、命令前缀、资源配额及自测方式见[总题面](../../README.md)。

维护有向网络，求带流量上下界及临时锁定的最小费用流，并查询最优流中各边的可取区间。

## 1. 对象

维护一个有向多重图。顶点编号 0 到 n-1。每条边有唯一数字 id、固定端点 u 和 v，以及可变下界 lo、上界 hi、单位费用 cost。允许自环和同端点的多条边。各边各自分配一个整数流量 f。

每个顶点有整数 balance。可行流必须同时满足：

- 每条边满足 lo ≤ f ≤ hi。
- 对每个顶点，所有出边流量之和减去所有入边流量之和等于 balance。自环在两边各计一次，净贡献为零。balance 为正代表净流出。
- 查询若临时锁定了某条边的流量，还必须满足该锁定值。

总费用是所有边的 cost × f 之和，包括自环。负费用允许。若可行，先将总费用最小化，然后按**边 id 数值递增**排列流量，从所有最小费用流中取流量向量字典序最小者。每条锁定都只在当前查询有效。

## 2. 环境和限制

基准环境为 Windows / CPython 3.14.2。将解法写在 `tide.py` 中，仅使用 Python 标准库。程序从标准输入读取命令，向标准输出写入回复。除导入标准库外，程序不读写文件、不联网、不启动子进程，也不调用外部本机代码。允许使用通用缓存。

- 1 ≤ n ≤ 24，0 ≤ 边数 ≤ 96。id 为 0..2^32−1 整数，互不相同。端点编号有效。
- 0 ≤ lo ≤ hi ≤ 2^63−1。费用为 −(2^63−1)..2^63−1。每个 balance 为 −2^70..2^70。余额总和可以不为零。
- 每进程最多 5000 条命令，其中 solve 最多 48 条。每个 solve 最多 16 个临时锁定和 16 个区间查询。
- 每场景新进程。每进程 60 秒、峰值工作集 512 MiB。在线场景中每条回复限 5 秒。
- UTF-8 NDJSON。每行一个合法 JSON 对象，每读一条立即回复并 flush，不能等 EOF。stdout 只含回复，LF 行尾，stderr 为空，EOF 退出码 0。可以忽略空白输入行。
- 响应对象字段顺序、空白任意。字段集合、类型、值与数组顺序必须匹配。整数不得转成字符串、浮点或布尔。拒绝重复 JSON 字段。所有运算数学上精确，费用和中间量可能超过 64 位。

## 3. 命令

第一条且仅第一条是 init。

```json
{"op":"init","vertices":2,"balance":[3,-3],"edges":[{"id":9,"u":0,"v":1,"lo":0,"hi":4,"cost":2},{"id":3,"u":0,"v":1,"lo":0,"hi":2,"cost":2}]}
```

init 固定顶点数、边 id 和端点。edges 初始顺序任意。其后可修改每条边的 lo、hi、cost 与各点 balance。余额和边参数的任意合法组合都允许，包括完全不可行的状态。

```json
{"op":"patch","edges":[[9,0,4,-1]],"balance":[[0,2],[1,-2]]}
{"op":"save","slot":31}
{"op":"load","slot":31}
```

- patch 的 edges 条目是 [id,lo,hi,cost]，完整替换该边的三个可变参数。balance 条目是 [顶点编号,新 balance]。每个列表中目标唯一，列表可以为空。没列出的参数保持当前值。整条命令作为一次更新。
- save 将所有可变参数复制到指定槽，覆盖旧值。load 恢复指定槽。槽号 0..31，load 保证槽已保存。后续更新、其他槽和再次 load 均不改变已保存快照。

init、patch、save、load 都回复恰好 {"ok":true}。

## 4. 查询

```json
{"op":"solve","pins":[[9,2]],"inspect":[3,9,3]}
```

- pins 是 [边 id,流量] 列表。id 必须存在，且每个 id 最多一次。锁定值为 0..2^63−1，可以超出边当前上下界。这种情况本次直接不可行。pins 内顺序任意。
- inspect 是边 id 列表，每项都存在，可重复。两个列表都可以为空。
- solve 不改变参数和快照，后续查询须独立解释各自的 pins。

不可行时仅返回：

```json
{"possible":false}
```

可行时返回：

```json
{"possible":true,"cost":6,"flow":[[3,1],[9,2]],"ranges":[[1,1],[2,2],[1,1]]}
```

上例使用初始参数，尚未执行 patch。cost 是最小总费用。flow 包含每条边的 [id,流量]，按**数字 id 递增**排列，表达前述规范最优解。ranges 与 inspect 逐项同序。每项 [最小流量,最大流量] 针对指定边单独计算，极值取遍**当前锁定条件下的所有最小费用流**。其他边可以为取得该极值而变化，含 id 更小的边。一条边的极值不要求和另一条边的极值同时实现。所有值均为精确整数。

在初始图中，不带 pins 求解并查询 [3,9] 时，规范流为 [[3,0],[9,3]]，两个区间分别为 [0,2] 与 [1,3]。锁定 id 9 为 0 导致不可行。锁定后应重新最小化费用，即使最小费用高于无锁时的最优值也可以。

负费用循环可以在所有 balance 为零时降低费用。自环也参与目标与字典序比较。即使任意两边的原始费用不同，它们仍可能处在同一个最优流变化中。例如两条不同路径的总费用相同。
