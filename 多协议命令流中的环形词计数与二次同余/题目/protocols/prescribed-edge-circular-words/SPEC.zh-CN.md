# 固定有向边重数的环形词计数 / Counting Circular Words with Prescribed Directed Edge Multiplicities

本页定义子协议。组合后的入口、命令前缀、资源配额及自测方式见[总题面](../../README.md)。

根据有向边的使用次数统计合法环形词、旋转等价类与前缀完成数，并查询规范词。

## 1. 边库存与环形词

顶点（颜色）编号为0..V-1，给定V×V非负整数矩阵M。长度N的**带位置词**是元组x=(x[0],...,x[N-1])，N=sum(M[u][v])。它合法当且仅当，对所有u、v，恰好有M[u][v]个下标i满足：

```text
x[i] = u and x[(i+1) mod N] = v
```

首尾相邻也算一次。边有方向，自环允许；相同端点的多次出现没有独立编号。不同的顶点序列才是不同词，不按边副本的排列另算方案。

矩阵始终满足每个顶点的总出度=总入度；**不保证连通**，允许孤立顶点。查询时1<=N<=200000。长度1需要一个自环。

## 2. 旋转、精确周期、规范词

`R_k(x)[i]=x[(i+k) mod N]`。necklace是合法词按旋转划分的等价类，不允许反射或换色。

精确周期是使R_p(x)=x的最小正整数p。若合法词是短块重复r次，则p=N/r，每个M[u][v]都能被r整除。

令G为所有矩阵元素的最大公约数（零元素参与gcd，等价于对非零元素取gcd）。查询时G>=1。periods只为 **p=N/r，r为G的正因子** 列行，按p严格递增，即使计数为零也保留；不为其他p列行。

规范词是全部合法带位置词中按**整数顶点编号**比较字典序最小的一个；不是比较编号的十进制字符串。不同起点的词也参与比较。

## 3. 环境、协议、限制

UTF-8 NDJSON，每行一条合法JSON命令。每读一条立即回复一行并flush，不等EOF。stdout只含协议响应，LF行尾，stderr为空，EOF退出0。可忽略空白输入行。

字段顺序和空格不限；响应字段集合、精确类型、数值与数组顺序必须匹配。整数不能用浮点数、字符串或布尔代替，不接受重复JSON字段。

- 基准环境为 Windows / CPython 3.14.2。将解法写在 `euler.py` 中，仅使用 Python 标准库。
- 1<=V<=16，矩阵元素是非负整数；任一初始化或修改后0<=N<=200000，count保证N>=1。
- 每进程最多5000条命令，其中count最多64条。
- 每个count：rotations、at分别最多32项，元素为0..2^2048-1整数，可重复、乱序、超范围。
- prefixes最多16项，每项是长度0..32的有效顶点编号数组，可重复、为空、长度>N或无法完成。
- count时G的正因子数量最多64，G的完整质因数分解由输入提供。
- 每进程60秒、峰值工作集512 MiB，每条在线响应最多等待5秒。计时包括启动、计算、输入输出。

除本文件和正常标准库导入外，不读其他文件、不写持久化文件、不联网、不启动子进程、不使用ctypes或调用外部EXE/DLL。允许通用缓存。

## 4. init

第一条且仅第一条命令：

```json
{"op":"init","vertices":2,"mod_factors":[[2,3],[3,2]],"edges":[[1,1],[1,1]]}
```

vertices为V，edges为M，行列按编号排列。行和等于对应列和。初始N允许为0。

mod_factors是计数模数m的完整质因数分解：每项[p,a]，p是实际素数，严格递增，a是正整数，m=product(p**a)。保证：

```text
2 <= m <= 2^63-1
each p**a <= 65536
```

输入保证合法，无须做整数分解或合法性检查。**m可能与N、精确周期或阶乘项不互素。** V和m在进程中固定。init清空快照，响应 `{"ok":true}`。

## 5. 修改与快照

### cycle

```json
{"op":"cycle","vertices":[0,1,0],"delta":2}
```

vertices是长度1..32的顶点数组，允许重复。沿该闭合游走的每一步（包括最后回到第一个顶点），给对应矩阵元素加delta：

```text
M[vertices[i]][vertices[(i+1) mod L]] += delta
```

delta是-200000..200000整数，可为0。重复有向边**按出现次数累计**，不能先去重；长度1给自环加一次。

输入保证修改后全部元素非负且N<=200000；闭合游走保持入出度平衡。没有查询时允许N=0。

例如[0,1,0]会改0->1、1->0、0->0各一次；[0,0]改0->0两次。响应 `{"ok":true}`。

### save / load

```json
{"op":"save","slot":31}
{"op":"load","slot":31}
```

slot为0..31。save复制整个矩阵并覆盖该槽旧值；load恢复，输入保证已保存。之后的修改、其他槽和再次load不改变已保存快照。查询不改变状态。

均响应 `{"ok":true}`。

## 6. count

```json
{"op":"count","gcd_factors":[],"rotations":[0,1,4],
 "prefixes":[[],[0],[0,0],[0,0,1,1]],"at":[0,1,2,3,4]}
```

gcd_factors是当前G的完整质因数分解，格式同mod_factors；G=1时为空。G与计数模数m是不同对象。

响应字段恰为：

```text
{
 "possible":P,
 "length":N,
 "words":W,
 "necklaces":K,
 "periods":[{"period":p,"words":W_p,"necklaces":K_p},...],
 "fixed_rotations":[...],
 "prefix_counts":[...],
 "witness":null or {"sha256":H,"at":[...]}
}
```

- possible：是否存在合法词，JSON布尔。**计数模m为0不等于不可行。**
- length：当前N，精确JSON整数。
- words：全部合法带位置词数量，模m。
- necklaces：全部旋转等价类数量，模m。
- periods：第2节规定的候选周期全部列出。每行只计精确周期恰为p的合法词及旋转类，分别模m；不是周期整除p，也不是直接返回缩小库存后的总数。
- fixed_rotations：与请求rotations同长同序，每项是满足R_k(x)=x的合法带位置词数，模m。
- prefix_counts：与请求prefixes同长同序，每项是前len(prefix)个顶点恰为该前缀的**完整长度N带位置词**数量，模m。空前缀等于words；长度>N为0。前缀内部使用哪些边就消耗哪些库存；剩余部分还必须正确闭合回第一个顶点，边副本仍不可区分。
- 不可行时仍返回全部字段与全部periods行，所有计数为0，witness=null。
- 可行时witness为规范词哈希和下标查询；at与请求同长同序，下标从0开始，>=N返回null。

所有计数先在非负整数意义下定义，再取模，结果为0..m-1整数。不能把整数整除改成对非单位求模逆。

## 7. 见证哈希

对以下字节串取SHA256，输出64个小写十六进制字符：

```text
b"EULER1"                      # 6 ASCII bytes, no NUL or newline
+ N.to_bytes(8, "little")      # unsigned little-endian
+ bytes(the N vertex IDs in the canonical word)   # one byte per ID, from 0 to 15
```

不编码边副本、模数、快照、分隔符或十进制文本，也不重复末尾闭合起点。

## 8. 例子

1. M=[[1,1],[1,1]]：合法词为0011、0110、1100、1001；words=4，necklaces=1，只有候选周期4，规范词0011。前缀[]、[0]、[0,0]、[0,0,1,1]的数量依次4、2、1、1。
2. M=[[0,2],[2,0]]：合法词为0101、1010；精确周期都为2。m=2时words=0但possible=true、necklaces=1。
3. M=[[2,0],[0,2]]：入出度平衡，但两个分离自环库存无法组成单个合法词，possible=false。
4. 边0->1、1->0、1->2、2->1各一次：规范词0121；前缀[0,1,0]无法完成，不能把“下一步有边”当成“剩余全程可完成”。
