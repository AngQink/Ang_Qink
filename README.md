# 多语言终端任务题库 / Multilingual Terminal Benchmarks

[中文](#中文) · [English](#english) · [新任务 / New tasks](#new-tasks) · [原题 / Original tasks](#original-tasks) · [GitHub Releases](https://github.com/AngQink/Ang_Qink/releases/latest)

## 中文

110 道新任务，每种语言或方言 5 道，另有原来的 19 道。每个题包单独发布，含 `题目/` 和 `答案/`。新题包括重放缺陷调试、合成生产器的格式逆向、故障恢复、配置迁移、数据查询、制品生成及编译依赖修复。题面和解析均为中英双语。

1. 将对应的 `题目/` 交给作答者。按 README 完成 `workspace/` 中的交付物并运行公开测试。
2. 从该题目录运行 `python 答案/评测/grade.py --candidate 题目/workspace --output report` 检查新题提交。去掉参数可验参考解。正式测试使用原始判据或冻结输入，与自测有部分重合。
3. 在仓库根目录用 `python compare.py --language rust --official` 批量验证。`--language` 接受下方标题括号内的键。按各题 README 配置本机工具链。Go 可从 PATH 或 `BENCH_GO` 找到。CUDA 可通过 `BENCH_MSVC_WRAPPER` 进入 MSVC 环境。

题面、参考解与独立结果校验的组织方式参考 Terminal-Bench。这里的执行入口是本地 CLI。正式数据与答案公开供复查，要盲测时只向模型提供题目目录，并在独立环境保管可信判据。 [Terminal-Bench 出题规范](https://github.com/harbor-framework/terminal-bench/blob/main/CONTRIBUTING.md)

## English

The collection adds 110 tasks, five per language or dialect, alongside the original 19. Each problem has one ZIP containing `题目/` and `答案/`. Tasks cover debugging, synthetic format reconstruction, recovery, configuration, data queries, artifact production, and build dependencies. Instructions and editorials are bilingual.

1. Give the solver the `题目/` directory. Complete the required artifact in `workspace/` and run the public tests.
2. From a problem's root, run `python 答案/评测/grade.py --candidate 题目/workspace --output report` to evaluate a new submission. Omit the arguments to verify the reference. Full and public suites overlap.
3. From the repository root, `python compare.py --language rust --official` runs only Rust's full suites. Language keys appear below. See each README for toolchain requirements. Go uses PATH or `BENCH_GO`. `BENCH_MSVC_WRAPPER` can initialize the MSVC environment for CUDA.

The separation of instructions, reference solutions, and executable verification follows the Terminal-Bench authoring approach. These packages run through a local CLI. For blind runs, provide only the problem directory and keep the trusted verifier and its data in a separate environment. [Terminal-Bench authoring guide](https://github.com/harbor-framework/terminal-bench/blob/main/CONTRIBUTING.md)
