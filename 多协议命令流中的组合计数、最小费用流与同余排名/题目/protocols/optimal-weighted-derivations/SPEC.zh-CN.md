# 动态加权文法的最优推导 / Optimal Derivations in a Dynamic Weighted Grammar

本页定义子协议。组合后的入口、命令前缀、资源配额及自测方式见[总题面](../../README.md)。

## 1. 对象与最优性

维护一个带非负整数成本的上下文无关文法。非终结符编号0..N-1，终结符为单字符a、b、c、d。
每条生产式有唯一的32位无符号整数id；内容相同但id不同的生产式是不同选择。

一棵推导树的每个节点使用一条生产式，节点标签为其id，子树按生产式右侧非终结符的左右顺序排列。
终结符生产式和空串生产式均为叶节点。树的产出为从左到右的终结符字符串。
树的成本为所有生产式节点的cost之和，使用精确整数；总和可以超过64位。

查询某个起始非终结符对给定word的推导：

1. 不存在有限推导树时，不可行。
2. 存在时求最小成本W，并计算**所有成本恰为W的推导树**数量。
3. 最优推导树可能有无穷多棵；无穷时单独标记，不对无穷取模。
4. 另从这些最小成本树中，先选择**节点总数最少**的，再按**生产式id的先序遍历序列**取字典序最小的一棵，称为规范见证。

计数计算所有最小成本树，不只计算最少节点的树。不同的展开执行先后顺序不另算方案；左右子树的选择独立。
先序序列先访问根，再访问左子树、右子树；id按整数比较，9小于10，不是按十进制字符串比较。
无穷最优树仍有定义良好的有限规范见证：节点数先于字典序比较。

## 2. 协议、规模与资源

输入输出为UTF-8 NDJSON，每行一个JSON对象；输入保证合法。
每读一条命令，立即输出并flush一条响应，不等待EOF。stdout仅输出协议响应，LF行尾；stderr为空，EOF退出0。
响应字段顺序和空格不限，字段集合、类型和值必须准确。整数不接受浮点数、字符串或布尔代替。

- `1 <= N <= 64`；生产式最多256条，其中双非终结符生产式最多64条；这两个数量包括禁用的生产式。
- 每条id为0..2^32-1的整数，各id唯一；数组顺序没有额外意义。
- 每条cost为0..2^63-1的整数。文法结构、id和计数模数在进程中固定，只能更新cost和启用状态。
- 查询word只含abcd，长度0..24；空串用""。
- 每进程最多5000条命令，其中parse最多32条。
- 快照slot为0..31，load引用保证已保存。
- 每个parse的at最多32项，每项为0..2^2048-1的JSON整数；重复、乱序和超出见证长度都合法。
- 模数 `2 <= mod <= 2^63-1`，可以为合数。
- 每场景60秒、峰值工作集512 MiB；在线交互每条最多等待5秒。
- 进程计时包含解释器启动、JSON 输入输出与计算。

测试环境为 Windows 与 CPython 3.14.2。实现须集中在 `ink.py`，只使用 Python 标准库。除正常导入标准库和读取本程序外，不得读取其他文件、创建持久化文件、联网、启动子进程、使用 `ctypes` 或加载系统 DLL。
可以缓存通用计算结果。程序须正确处理所有满足约束的输入，算法和内部表示不限。

## 3. init

第一条且仅第一条命令：

```json
{"op":"init","nonterminals":1,"mod":6,"rules":[
 {"id":0,"lhs":0,"rhs":[0],"cost":0,"enabled":true},
 {"id":7,"lhs":0,"rhs":["a"],"cost":3,"enabled":true}
]}
```

rhs只会是以下四种之一：

| rhs | 生产式 |
|---|---|
| `[]` | lhs产生空串 |
| `["a"]`（或b/c/d） | lhs产生一个终结符；该规则为叶节点 |
| `[B]`，B为整数 | lhs产生一个非终结符 |
| `[B,C]`，B/C为整数 | lhs产生两个有序非终结符 |

lhs和所有非终结符下标有效。enabled为JSON布尔值。禁用的生产式不能用于任何树。
init清空快照，响应 `{"ok":true}`。

## 4. 更新与快照

以下命令响应 `{"ok":true}`：

| 命令 | 含义 |
|---|---|
| `{"op":"weight","id":r,"cost":w}` | 更新该规则成本；禁用时也更新并保留新成本 |
| `{"op":"enable","id":r,"value":true}` | 设置该规则启用状态 |
| `{"op":"save","slot":s}` | 保存全部规则的cost和启用状态，覆盖该slot旧值 |
| `{"op":"load","slot":s}` | 恢复该快照；后续修改不影响快照 |

规则结构、模数和非终结符数量不变。查询也不改变文法或快照。

## 5. parse

```json
{"op":"parse","start":0,"word":"a","at":[0,1,100]}
```

start为有效非终结符。若不能推导word，只响应 `{"possible":false}`。
否则响应恰好为：

```text
{"possible":true,
 "cost":W,
 "infinite":I,
 "ways":K,
 "witness":{"nodes":M,"sha256":H,"at":[...]}}
```

- W：最小成本，JSON整数。
- I：最优推导树是否无穷多，JSON布尔。
- 若I=true，K必须为null；若I=false，K为有限最优树数对mod取非负模的整数。
- **有限K=0仍然可行**，也不表示无穷。
- M：规范见证的生产式节点总数，精确JSON整数；终结符和空串规则也各算1个节点。
- H：下节定义的规范见证SHA256，64个小写十六进制字符。
- witness.at与请求at等长；第j项是规范见证先序序列下标at[j]处的生产式id；下标从0开始，0是根。若at[j]>=M，返回null。

见证可能极大，不能要求把整棵树或整个先序序列展开。相同结构子树可以共享，但左右出现次数仍计入M和先序下标。

## 6. 见证哈希

每个树节点的二进制编码为：

```text
b"DERIVE1"
+ id.to_bytes(4, 'little', signed=False)
+ bytes([arity])
+ the children's 32-byte raw SHA-256 digests in left-to-right order
```

对此编码取SHA256即该节点摘要，根摘要以小写hex输出。
`DERIVE1`是7个ASCII字节，不含NUL或换行。
arity是**非终结符子节点数**：空串和终结符规则为0，单非终结符为1，双非终结符为2。
连接的是32字节原始摘要，不是64字节hex字符串。成本、启用状态、输入位置、lhs和终结符字面量不另写入节点编码；规则id固定且唯一。

## 7. 语义例子

- `S -> S`成本0，`S -> "a"`成本3：word="a"最小成本3，最优树无穷多；规范见证只用终结符规则，M=1。
- 上述自循环成本改为1后，最小成本仍为3，但最优树仅1棵。
- 两条不同id的`S -> "a"`都成本0：最优树2棵，mod=2时ways=0；规范见证选id更小的规则。
- `S -> A A`、`A -> ε`均成本0：空串见证有3个节点，不是0；若A有两条相同内容但不同id的空串规则，则S的最优树有2*2=4棵。
- 文法其他部分有环，不代表当前目标有无穷最优树。只有可用于当前最小成本推导的循环才相关。
- 无穷计数、有限的最短规范见证和极大的见证节点数，可以同时出现。
