# 动态森林的最大权独立集 / Maximum-Weight Independent Sets in Dynamic Forests

实现单文件 `forest.py`。维护一个顶点带权的无向森林，支持在线连边、断边和改权，并精确回答连通分量的最大权独立集、最优方案数，以及强制两个顶点状态后的结果。

算法与数据结构由你决定。需要同时满足语义、在线响应和资源限制。

## 1. 运行环境

测试环境为 Windows 与 CPython 3.14.2。实现须集中在 `forest.py`，只使用 Python 标准库。除正常导入标准库和读取本程序外，不得读取其他文件、创建持久化文件、联网或启动子进程。

输入输出为 UTF-8 NDJSON，每行一个 JSON 对象，stdout 只输出协议响应，行尾为 LF。每读取一条命令，必须立即输出并 flush 一条响应，不能等 EOF。输入可能在收到上一条响应后才继续生成。EOF 正常退出，返回码0；stderr 应为空。

所有输入保证合法且满足下述约束，不要求为无效JSON、非法操作或越界提供错误处理。输出对象的字段次序和分隔空格不限，字段集合、类型和值必须准确；整数必须输出为JSON整数，布尔值为JSON布尔值。

## 2. 数学定义

- 顶点为 `0..n-1`。每个顶点u具有整数权重w[u]。
- 图始终是无自环、无重边的无向森林，可以不连通。
- 一个独立集是顶点子集S，其中没有一条边的两个端点同时属于S。空集合法，权重为0。
- 集合权重为其顶点权重之和。最大权独立集可以有多个；**方案数计算不同的顶点子集**，不计算遍历顺序或选择过程。
- 所有查询只考虑所指定的那个连通分量；其他分量不参与权重或方案数。
- 权重之和使用精确整数，不能用浮点数近似，也不对权重取模。顶点权重为有符号64位整数（含两端），答案之和可能超出64位。
- 方案数对初始化给定的m取非负模。m可以是合数。**ways=0只是计数的模结果，不代表无解。** 可行性由明确的possible字段表示。
- 查询不改变抽象图、顶点权重或其他查询的数学结果。

## 3. 初始化

第一条且仅第一条命令为：

```json
{"op":"init","weights":[w0,w1,...],"edges":[[u,v],...],"mod":m}
```

n等于weights长度，保证 `1 <= n <= 100000`；edges是合法森林，每个无向边仅出现一次，端点顺序任意。m为整数，满足 `2 <= m <= 2147483647`，不保证为素数。

响应：`{"ok":true}`。

## 4. 修改

以下操作统一响应 `{"ok":true}`：

| 命令 | 语义与保证 |
|---|---|
| `{"op":"set","u":u,"w":w}` | 将u的权重替换为w；允许与原权重相同 |
| `{"op":"link","u":u,"v":v}` | 添加无向边(u,v)；保证u、v在不同连通分量 |
| `{"op":"cut","u":u,"v":v}` | 删除无向边(u,v)；保证该边存在；端点顺序任意 |

顶点集合与m在一个进程中固定。没有额外的隐式根，也没有未说明的重置操作。

## 5. 单顶点条件查询

命令：`{"op":"ask","u":u}`。

令C为u所在连通分量。响应必须恰好为：

```text
{"n":|C|,
 "best":{"weight":W,"ways":K},
 "out":{"weight":W0,"ways":K0},
 "in":{"weight":W1,"ways":K1}}
```

- best：C中无额外限制的最大权独立集及其方案数模m。
- out：强制u不属于独立集时的最优权重和方案数。
- in：强制u属于独立集时的最优权重和方案数。

这三种问题在森林中总是可行。in的权重可能为负。若out与in的最优权重相同，best的ways应为两者ways之和模m，因为这两类顶点子集互不相同。

## 6. 双顶点条件查询

命令：`{"op":"pair","u":u,"v":v,"su":s,"sv":t}`，s与t分别为0或1。0表示强制该顶点不选，1表示强制选择。

1. 若u、v不连通，仅响应 `{"connected":false}`，不把两个分量合并求解。
2. 若连通但条件不可同时满足，仅响应 `{"connected":true,"possible":false}`。
3. 否则响应 `{"connected":true,"possible":true,"weight":W,"ways":K}`。

W和K是**整个连通分量**在两个强制条件下的最优权重和方案数模m，不是仅对u到v的路径求解。路径外的分支也必须计入。

允许u=v：s=t时相当于一个强制条件，s!=t时不可行。相邻的两个顶点都强制选中时也不可行。可行答案即使K=0也必须输出possible=true。

## 7. 例子

三点星形：边为(0,1)、(0,2)，权重全为0，m=4。全部独立集是：空集、{0}、{1}、{2}、{1,2}。

`ask 0` 的响应为：

```json
{"n":3,"best":{"weight":0,"ways":1},"out":{"weight":0,"ways":0},"in":{"weight":0,"ways":1}}
```

`pair(0,0,0,0)` 是可行的，响应：

```json
{"connected":true,"possible":true,"weight":0,"ways":0}
```

因为有4个最优集合满足0不选，其计数模4为0。这个零不能被当作“不存在”。

将顶点0改为权重-7，单独强制选择0时仍可行，最优权重-7，ways=1。

## 8. 规模与资源

- 每个独立进程最多60000条命令（包括init）；n最多100000，初始边数最多n-1。
- 每个set的新权重在 `[-2^63,2^63-1]` 内。
- 进程峰值工作集上限为 **512 MiB**。每个场景限时 **60 秒**，包含解释器启动、JSON 输入输出与命令处理。
- 在线交互检查会在每条命令后等待响应，最多5秒；不允许读完整个未来脚本再离线求解。
- 数据包括长路径、高度数顶点、打乱编号的大树、反复切换查询顶点、非单位和零计数、频繁改权/切边/重连，以及同时具有这些性质的组合。

可以缓存、共享或重组内部结构，但不能让查询顺序影响结果，也不能把不可逆的模运算当作普通实数除法。每次查询遍历整个大分量或把所有方案计数永久保留为无限精度整数，都可能无法满足资源限制；实现选择仍由你决定。
