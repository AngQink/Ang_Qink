# 压缩持久化序列的区间查询 / Range Queries on Compressed Persistent Sequences

实现单文件 `loom.py`：一个维护超长整数序列和分支版本的流式进程。序列可以通过重复与引用增长到 **2^60 个元素**；后续编辑必须保持所有旧版本不变。不能把虚拟序列展开成数组。

本题没有要求使用特定数据结构。你的目标是同时满足下面的语义、协议和资源限制。

## 1. 运行环境

测试环境为 Windows 与 CPython 3.14.2。实现须集中在 `loom.py`，只使用 Python 标准库。除正常导入标准库和读取本程序外，不得读取其他文件、创建持久化文件、联网或启动子进程。

stdin、stdout 为 UTF-8 NDJSON，每行一个 JSON 对象，换行必须是 LF。stdout 只输出协议响应；对象成员顺序、分隔空格不影响判定。每读一个命令，必须立即输出并 flush **一个**响应，不能等 EOF 再回答。输入可能在收到上一条响应后才继续产生。EOF 正常退出，返回码 0；stderr 应为空。

输入保证是合法 JSON，且所有类型、版本引用、范围和规模均符合本规范；不考察无效输入的错误处理。JSON 数字均为整数，不使用布尔值冒充整数。不要把大整数转换成浮点数。

## 2. 数值、版本与坐标

模数 `P = 1000000007`；哈希基数 `B = 911382323`。

序列元素始终为 `[0,P)` 中的整数。初始值和变换系数是有符号 64 位整数（含两端），其运算结果取数学意义的非负模 P。

启动时只有版本 **0**，它是空序列，永久存在。每执行一次创建版本的命令，分配下一个整数版本号，从 1 开始严格递增，永不复用；即使操作结果为空、内容不变或仅引用旧内容，也必须分配新号。

所有旧版本不可变。一个版本可以引用同一个旧版本多次，也可以把自己的片段插入自己；任何引用都代表该命令开始时的值。`drop` 只移除一个版本句柄，不能破坏其他版本共享的内容。

范围均为 **0 起始、左闭右开 `[l,r)`**，保证 `0 <= l <= r <= n`。空范围、整段范围、末端空范围均合法。`at` 保证 `0 <= i < n`。长度和坐标是普通整数，不对 P 取模。

## 3. 创建版本的命令

以下命令统一响应 `{"v":新版本号,"n":结果长度}`，且不改变其输入版本。

| 输入 | 结果 |
|---|---|
| `{"op":"new","values":[x0,x1,...]}` | 给定元素分别模 P 后组成的新序列；允许空列表 |
| `{"op":"concat","left":u,"right":v}` | 版本 u 的全部元素，紧接版本 v 的全部元素；允许 u=v |
| `{"op":"repeat","v":v,"times":k}` | 版本 v 首尾连接 k 次；k=0 或 v 为空时结果为空 |
| `{"op":"slice","v":v,"l":l,"r":r}` | 版本 v 的子序列 `[l,r)` |
| `{"op":"splice","v":v,"l":l,"r":r,"src":u,"sl":a,"sr":b}` | 把 v 的 `[l,r)` 替换成 u 的 `[a,b)`；其余元素保持顺序；允许 u=v 且区间重叠 |
| `{"op":"reverse","v":v,"l":l,"r":r}` | 只反转 v 的 `[l,r)` |
| `{"op":"edit","v":v,"l":l,"r":r,"a":a,"b":b,"c":c}` | 对该范围原有的第 j 个元素执行 `y[j]=(a*x[j]+b+c*j) mod P`，范围外不变 |

`edit` 的 j 从所选区间的左端重新从 0 计数，与该区间在整个版本中的位置无关。变换在执行时得到固定数值；后续剪贴、复制、反转只移动这些数值，**不会按新坐标重新执行旧变换**。

例如 `[2,5,7]` 对 `[1,3)` 做 a=2,b=3,c=4，结果是 `[2,13,21]`；再整体反转得到 `[21,13,2]`。原版本仍是 `[2,5,7]`。

自我剪贴示例：v=`[1,2,3,4]`，`splice(v,1,3,src=v,sl=0,sr=3)` 的结果是 `[1,1,2,3,4]`。源是编辑前的完整版本。

## 4. 查询与释放

### `{"op":"at","v":v,"i":i}`

响应 `{"value":该位置元素}`。

### `{"op":"query","v":v,"l":l,"r":r}`

设所选子序列为 x[0..m-1]，响应中必须恰有以下六个成员：

```text
{"n":m,
 "sum":       sum(x[j]) mod P,
 "square":    sum(x[j]*x[j]) mod P,
 "moment":    sum(j*x[j]) mod P,
 "forward":   sum(x[j]*B^j) mod P,
 "backward":  sum(x[j]*B^(m-1-j)) mod P}
```

所有求和均遍历 `j=0..m-1`；这里的 j 也相对于**所查询的子序列**从 0 开始。空区间响应为 `{"n":0,"sum":0,"square":0,"moment":0,"forward":0,"backward":0}`。

查询只要求按公式输出这些哈希值，无需额外判定两段序列是否精确相等。

### `{"op":"drop","v":v}`

移除活动版本 v，响应 `{"ok":true}`；不分配新版本号。不会要求 drop 0、重复 drop 或在之后使用已 drop 的版本。即使内容等价，其他版本也仍然有效。允许利用释放回收内存。

## 5. 输入规模与验收边界

- 每个独立进程最多 60,000 条命令。
- 单条 new 最多 4,096 个元素；一个进程所有 new 的元素数之和最多 100,000。
- 同时活动版本最多 12,000 个，包含版本 0；创建的版本总数可更多。
- 所有版本长度均不超过 2^60。repeat 的 k 在 `[0,2^60]`，并保证结果长度不超限。
- 进程峰值工作集上限为 **512 MiB**。每个场景限时 **20 秒**，包含解释器启动、输入输出与命令处理。流式交互场景中每个响应最多等待 5 秒。
- 压力场景包括大量存活的分支版本、重复引用同一大段内容、持续剪贴形成的碎片、交错反转与位置相关变换、很深的编辑历史、以及大量创建后释放的版本。

只维护一个可变副本、不正确地传播坐标变换、错误处理共享节点、按虚拟长度循环、只在 EOF 后计算、或永久保留已释放的全部历史，均可能无法完成这些场景。实现方式由你决定；公开测试仅提供基本反馈。
