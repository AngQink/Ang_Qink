查询有向最小费用根树的精确数量、字典序反查与排名，以及指定边参与最优树的次数。

## 1. 有向根树

维护一个有向多重图。顶点编号 0 到 n−1。每条边有唯一数字 id、固定起点 u、终点 v、可变整数费用 cost 和可变启用状态。允许平行边和自环。端点及费用相同的两条边仍是不同选择。

每次查询指定一个根 root。一个可行根树须满足：

- 根没有入边，每个其他顶点恰好选择一条启用入边。
- 从根沿选中边的正方向能到达每个顶点。因此自环和脱离根的环不能被选中。
- 查询的 pins 中每条边都必须被选中。

树的费用为所选边的费用之和。负费用允许。最优树指满足本次 pins 的全部可行树中费用最低者。

一个树向量按**终点顶点编号递增**列出所选边 id，跳过根。例如根为 1，n=4 时依次列终点为 0、2、3 的边 id。按向量中**整数 id**的字典序给最优树排序，位置从 0 开始。不同选边集合对应不同向量。

## 2. 环境和限制

基准环境为 Windows / CPython 3.14.2。将解法写在 `anchor.py` 中，仅使用 Python 标准库。程序从标准输入读取命令，向标准输出写入回复。除导入标准库外，程序不读写文件、不联网、不启动子进程，也不调用外部本机代码。允许使用通用缓存。

- 1 ≤ n ≤ 18，0 ≤ 边数 ≤ 80。id 为 0..2^32−1 整数，**所有边 id 唯一**。端点有效。
- cost 为 −2^63..2^63−1 整数，总费用可能超出 64 位，输出使用精确整数。
- 每进程最多 5000 条命令，其中 query 最多 32 条。一条 query 最多 12 个 pins，4 个 at，4 个 probes 和 12 个 uses。
- 每场景新进程。每进程 60 秒、峰值工作集 512 MiB。在线场景每条命令的回复限 5 秒。
- UTF-8 NDJSON。每行一个合法 JSON 对象。每读一条立即回复并 flush。stdout 仅含回复，LF 行尾，stderr 为空，EOF 退出 0。可忽略空白输入行。
- 对象字段顺序和 JSON 空格不限。字段集合、类型、值与数组顺序须匹配。整数不可用布尔、浮点或字符串表示。拒绝重复 JSON 字段。

## 3. 初始化、更新及快照

第一条且仅第一条为 init。启用状态是布尔值，边初始顺序任意，顶点数、边 id 和端点随后保持不变。

```json
{"op":"init","vertices":3,"edges":[{"id":9,"u":0,"v":1,"cost":5,"enabled":true},{"id":2,"u":0,"v":1,"cost":5,"enabled":true},{"id":3,"u":0,"v":2,"cost":2,"enabled":true},{"id":8,"u":1,"v":2,"cost":2,"enabled":true}]}
```

```json
{"op":"cost","id":9,"cost":-9}
{"op":"enable","id":2,"value":false}
{"op":"save","slot":31}
{"op":"load","slot":31}
```

- cost 替换该边费用，不改变启用状态。enable 替换启用状态，不改变费用。两种修改的 id 均存在。禁用边也可以改费用。
- save 复制保存全部边的费用和启用状态，覆盖旧槽。load 恢复该槽状态。槽号 0..31，load 保证槽已保存。后续修改和再次 load 均不改变已保存快照。

这些命令均回复恰好 {"ok":true}。

## 4. 查询

```json
{"op":"query","root":0,"pins":[],"at":[0,2,4],"probes":[[2,4],[9,8],[7,7]],"uses":[2,3,99]}
```

- root 为有效顶点。pins 中 id 存在且在本列表中各出现一次，顺序任意。如果指定了禁用边、自环、以根为终点的边，或同终点的不同边，就无法构成可行树。pins 仅对本次查询有效。
- at 与请求 at 同序。每项是 0..2^2048−1 的整数，查询对应位置的**完整树向量**，越界为 null。序号可乱序或重复。
- probes 与请求 probes 同序。每项请求是长度 n−1 的整数向量，元素是 0..2^32−1，可重复、可不在图中，也可组成非树、非最优树或违反 pins。before 是树向量严格小于该探针的**最优树数**，member 是探针是否为本次查询的最优树向量。
- uses 与请求 uses 同序。每项请求是 0..2^32−1 的 id，可重复、可不在图中。结果是本次查询的最优树中选用了该边的树数。
- 所有计数为精确非负整数。四个请求列表可为空。不可行时 possible=false、cost=null、count=0，所有 at 项为 null、所有 probes 项为 {"before":0,"member":false}、所有 uses 项为 0。仍返回全部字段。
- 查询不修改图或快照。n=1 且 pins 为空时，存在一棵费用为零的空树。

以上例的初始图和查询为例，最优向量依次为 [2,3]、[2,8]、[9,3]、[9,8]。回复为：

```json
{"possible":true,"cost":7,"count":4,"at":[[2,3],[9,3],null],"probes":[{"before":1,"member":false},{"before":3,"member":true},{"before":2,"member":false}],"uses":[2,2,0]}
```

若 pins=[9]，最优向量仅 [9,3]、[9,8]，费用仍为 7。若 pins=[2,9]，两条边都指向同一顶点，该查询不可行。负权环不会被整环计入树。局部最便宜的入边组合可能没有从根出发的路径。
