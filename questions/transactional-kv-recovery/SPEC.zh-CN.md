# 事务键值存储与预写日志恢复 / Transactional Key-Value Storage and Write-Ahead Log Recovery

你接手了一个单进程、可交错执行事务的键值数据库。它在正常演示中看似可用，但在事务交错和断电恢复时会给出错误结果。修复当前目录的程序，使它满足下面的协议。可重写实现；入口必须保留为 `chronicle.py`。

## 运行与自测

```text
python -B chronicle.py --db data
python -B -m pytest public_tests -q -p no:cacheprovider
```

第二条命令运行公开测试，需要 pytest。

测试环境为 Windows 与 CPython 3.14.2。数据库程序只使用 Python 标准库，不能调用外部数据库、启动其他进程或联网。数据只能持久化到 `--db` 目录下的 `journal.wal`，不得创建其他持久化数据库或索引。可以在内存中建立索引。

输入、输出均为 UTF-8 NDJSON，一行一个 JSON 对象。每处理一个输入必须立即输出并 flush 一个结果，不能等待 EOF；stdout 只输出结果。EOF 丢弃所有未提交事务并正常退出。错误信息可写 stderr。

可以使用多个 Python 源文件。程序不能依赖其他类型的附加资源文件。命令输入保证符合下面的类型和事务生命周期约束。无需处理 JSON 语法错误、无效事务 ID、无效保存点、并发进程打开同一库或磁盘写入失败。

## 数据与版本

键和值都是由 Unicode 标量组成的字符串，允许空串、NUL、换行和非 ASCII 字符，不做 Unicode 归一化。键按 UTF-8 编码的无符号字节字典序排列。不存在的键返回 JSON `null`，与值 `""` 不同。

全局已提交版本从 0 开始。`begin` 固定事务的快照版本；后续读取必须是该版本的已提交状态，再覆盖本事务的待提交写入。其他事务提交后也不能改变这个快照。禁止在 begin 时复制整个数据库：大量长事务与短事务会交错存在。

每个事务有一个写覆盖表：同一个键只保留最后一次 `put` / `delete`。`delete` 不存在的键也必须保留为一次写入。只要最终覆盖表非空，成功提交就增加一个版本，即使值没有实际改变。覆盖表为空的成功提交不增加版本，返回提交时的当前全局版本。

## 命令

每个例子右边是完整响应；没有额外字段。`tx` 和 `name` 都是非空字符串。

| 输入 | 响应 |
|---|---|
| `{"op":"begin","tx":"a"}` | `{"ok":true,"version":V}`，V 为开始时的全局版本 |
| `{"op":"get","tx":"a","key":"k"}` | `{"value":S}`，S 是字符串或 null |
| `{"op":"scan","tx":"a","start":"a","end":"z"}` | `{"items":[["key","value"],...]}` |
| `{"op":"put","tx":"a","key":"k","value":"v"}` | `{"ok":true}` |
| `{"op":"delete","tx":"a","key":"k"}` | `{"ok":true}` |
| `{"op":"savepoint","tx":"a","name":"s"}` | `{"ok":true}` |
| `{"op":"rollback","tx":"a","name":"s"}` | `{"ok":true}` |
| `{"op":"abort","tx":"a"}` | `{"ok":true}` |
| `{"op":"commit","tx":"a"}` | 成功 `{"ok":true,"version":V}`；冲突 `{"ok":false,"error":"conflict"}` |

`scan` 返回半开区间 `[start,end)` 内的全部可见键值，升序、不含已删除键。边界 `null` 分别表示负无穷和正无穷；两个边界相等时返回空，但仍登记这个空区间。非 null 边界保证 start <= end。不得用字符串哨兵代替无穷。

`savepoint` 保存当前写覆盖表，并压入保存点栈。活动保存点名称不重复。`rollback` 恢复目标保存点的写覆盖表，并删除它之后建立的保存点；目标本身保留，可以再次回滚。保存点与回滚都不改变快照版本。

**读取依赖不回滚。** 每次 `get` 都登记该键，包括读到不存在或读到本事务写入的情况；每次 `scan` 都登记完整区间，包括空结果、只含本事务写入的结果。回滚可以撤销写入，但不能撤销已经登记的读取依赖。

`commit` 无论成功或冲突都会结束事务；`abort` 结束事务。结束后的 ID 可以重新使用。

## 提交时的冲突规则

设事务开始于版本 S。在提交时，只要存在一个在 **S 之后被成功写事务触及的键**，且该键满足以下任一条件，就拒绝整个事务：

1. 该键出现在当前待提交写覆盖表中；
2. 该键曾被本事务 get；
3. 该键落入本事务任意一次 scan 登记的区间。

“触及”包括删除不存在的键、写入相同值、先删除再重建，以及后来又恢复原值。必须保留足以发现这些情况的信息；仅比较当前值与快照值不正确。

检查的是其他已经成功提交的事务；本事务尚未提交的写入不算。冲突必须整笔拒绝，不允许部分写入。只读事务也执行相同的读取冲突检查。读取依赖之外的键变动不引发冲突；scan 的上界不属于区间。

## WAL 二进制协议

`journal.wal` 是唯一持久化状态，必须能兼容已有文件。不存在或长度为 0 时，创建/初始化为下面的 8 字节文件头：

```text
43 48 52 4f 4e 31 0d 0a    # b"CHRON1\r\n"
```

非空文件保证具有正确文件头。文件头后是零个或多个帧，所有整数是**无符号小端定宽整数**：

```text
frame := payload_length:u32 | payload:bytes | crc32:u32
crc32 := zlib.crc32(payload) & 0xffffffff

payload := commit_version:u64 | operation_count:u32 | operation*
put     := tag:u8=1 | key_length:u32 | key:utf8 | value_length:u32 | value:utf8
delete  := tag:u8=2 | key_length:u32 | key:utf8
```

合法 payload 长度为 12..8,388,608 字节。operation_count 必须大于 0；一个帧里的键必须按编码字节严格递增，因此没有重复键。UTF-8 必须严格合法；禁止未消费的 payload 尾字节。版本从 1 开始逐帧严格加一。每个成功的非空写事务只追加一个合法帧，内容等于最终写覆盖表。只读提交、abort 和冲突事务不能产生帧。

启动时只接受从文件头起连续合法的最长帧前缀。遇到任何截断、非法长度、错误 CRC、非法操作编码、非法 UTF-8、重复/乱序键、零操作、错误版本或多余字节，就停止；**不得寻找后续看似有效的帧**。把文件截断到最后一个合法帧的末端，再接收输入。修复截断必须 flush 并 `os.fsync`。合法帧前缀的字节不得改写。

提交顺序必须是：验证冲突 → 构造并追加完整帧 → flush → `os.fsync` → 发布内存版本 → 输出成功。收到成功响应后即使进程立即被强制结束，重启也必须能读到该提交。不要求解决磁盘写入失败，也不要求模拟真实硬件故障。不得重写、压缩或重新排列已有合法帧。

## 规模与资源

单个合法帧不超过 8 MiB；单个 WAL 不超过 64 MiB；最多 30,000 个不同键、100,000 个已提交版本、2,000 个同时活动事务。数据与命令可以包含很长的 Unicode 字符串。总输入规模有限，不要求无限运行或历史垃圾回收。

评估包含约 25,000 个预置键、1,500 个长期快照和交错提交。单个数据库子进程的峰值工作集上限为 320 MiB，该场景限时 25 秒，其他单场景限时 15 秒。资源限制只针对数据库进程。可以用共享的版本历史表达快照。

## 两个需要正确处理的交错

例一：A scan `["m","n")` 得到空结果；B 在 `"moon"` 写入并提交。A 再次 scan 仍应为空，但 A commit 必须冲突。

例二：A 建立保存点，读取不存在的 `"ghost"`，再回滚；B 删除不存在的 `"ghost"` 并提交。A commit 仍必须冲突。空区间 `["x","x")` 则不会因任何键的变化产生范围冲突。
